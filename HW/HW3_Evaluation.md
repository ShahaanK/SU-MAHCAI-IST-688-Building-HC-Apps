Both model IDs were confirmed against each vendor's live model list before the run.

`streamlit.testing.v1.AppTest`, not by calling the APIs separately. The transcripts
therefore exercise the same scraping, prompt assembly, and buffer logic that a user
of the deployed app hits.

## The three questions, and why I picked them

The questions were chosen so that the two documents **do not overlap** on the answers.
If both pages covered everything, every scenario would score the same and the
comparison would show nothing. So each question targets a different coverage pattern:

**Q1. "How far apart are the bases, and how far is the pitcher's mound from home plate?"**
Answerable **only from Doc 1**, which gives exact figures (90 feet between bases,
60.5 feet to the mound). The PBS page describes the diamond but contains no
measurements at all. This question tests whether adding a second, larger document
*dilutes* an answer the model could already give — a real risk when you stuff more
text into a prompt.

**Q2. "What is ERA, and how exactly is it calculated?"**
Answerable **only from Doc 2**, whose statistics section defines Earned Run Average
and gives the computation in prose ("multiplying the total number of earned runs by
nine and dividing by the number of innings pitched"). Doc 1's Basics page never
mentions ERA. This is the mirror image of Q1, and it also tests honesty: with Doc 1
alone, the correct behavior is to refuse rather than recite ERA from pre-training.

**Q3. "Explain what happens when a batter is walked, name all nine defensive positions, and tell me whether the game can end in a tie."**
A three-part question that **requires both documents**. The walk rule is in both.
The nine positions appear *only* in Doc 2 (the glossary entry for "Fielder"). The
tie/extra-innings rule appears *only* in Doc 1 ("There are no ties in Baseball").
No single page can answer all three parts, so this question directly measures
whether the bot can synthesize across sources in one answer.

A fourth turn — *"What was the very first thing I asked you?"* — was appended to
every run to exercise the conversation buffer. It is a memory probe, not a content
question, and is discussed separately below.

## (i) Did having both documents improve the answers?

**Yes — substantially, and for a specific reason: the two pages are complementary
rather than redundant.** Coverage went from 3/5 to 5/5 for *both* models.

The clearest case is Q3. With Doc 1 only, both models explicitly failed the
positions sub-question. GPT-5.5 (S1): *"it specifically mentions the pitcher and
catcher, but it does not list all nine defensive positions."* Opus (S2) marked it
❌ outright and noted the site has a separate "Fielding and Positions" page it
didn't have. With both documents, both models produced the complete numbered list
from the PBS glossary **and** the no-ties rule from How Baseball Works — pulling
two facts from two different sources into a single coherent answer. That is genuine
synthesis, not concatenation.

The supplementary runs confirm the effect is bidirectional. With PBS alone (S5/S6),
the models could list the nine positions but could no longer give any field
dimensions or explain extra innings — the exact facts Doc 1 supplied. So each
document repairs a specific hole in the other.

**Adding the second document cost nothing.** This was the risk Q1 was designed to
catch: the second page more than doubled the context, so a diluted or hedged answer
was plausible. It didn't happen. Q1 was answered correctly and with the same
confidence in S3/S4 as in S1/S2, and both models correctly attributed the figures
to the How Baseball Works page. Attribution actually got *better* with two sources —
with one document the models say "the page," with two they name which page each fact
came from, which makes the answers easier to verify.

One quality improvement is easy to miss: given both pages, Opus quoted PBS's
*precise* strike-zone definition (kneecaps to the midpoint of shoulders and
uniform pants) instead of Doc 1's vaguer "above the hitter's knees, below the mid
point of his waist and shoulders." With two sources available the model can pick the
better-worded one. More documents improved not just *coverage* but *precision*.

The honest caveat: the improvement comes from the documents being complementary. Two
pages covering the same ground would add cost and latency for no gain, and every extra
document is re-sent on every turn, so this does not scale indefinitely.

## (ii) Which model was best?

**Claude Opus 5 produced the better answers; GPT-5.5 was far more efficient. For this
assignment's purpose, Opus wins — but the margin is narrower than the length
difference suggests.**

On raw correctness they tied: both scored 3/5 with one document and 5/5 with two,
and neither hallucinated. The difference is in the quality of the behavior around
the answer:

**Where Opus was better**

1. **More useful failures.** Asked about ERA with only Doc 1, GPT-5.5 said it wasn't
   covered and stopped. Opus said it wasn't covered, then noticed that the scraped
   navigation menu listed a separate "Statistics" page, told the user that's where
   the answer lives, and offered to explain it if given that page. It turned a dead
   end into a next step — from information genuinely present in the scrape.
2. **Explicit coverage marking.** On the three-part Q3, Opus tagged each sub-answer
   ✅/❌ so it was immediately obvious which parts the sources could support.
3. **Volunteering adjacent facts.** On Q1 it added the outfield wall distance
   (325–450 ft) and the 17-inch home plate without being asked, and flagged that
   PBS defines "error" only indirectly — a genuinely useful caveat about the limits
   of the source material.
4. **Richer recall.** On the memory probe, Opus restated both the earlier question
   *and* a summary of its own earlier answer; GPT-5.5 restated only the question.

**Where GPT-5.5 was better**

1. **Speed** — roughly 2.5× faster end to end (9.1 s vs 27.9 s for a four-turn
   conversation with both documents). For a streaming chat UI that gap is very
   noticeable.
2. **Concision** — it answered Q1 in two lines. Opus's extra context is a bonus when
   you want it and noise when you don't.
3. **Cost** — 2.3× fewer output tokens per conversation, on top of Opus being the
   more expensive model per token.

**Verdict.** For a homework chatbot whose job is explaining a document to a
newcomer, Opus 5's thoroughness, its sub-answer coverage marking, and especially its
constructive handling of gaps make it the better choice, and its extra verbosity is
mostly *useful* verbosity rather than padding. If this were a high-traffic
production app, GPT-5.5 would be the more sensible default: it got every factual
answer right, at a fraction of the latency and cost. The fair summary is that the
models were equally *accurate* and differed in *manner* — so the pick depends on
whether you are optimizing for depth or for responsiveness.

## The conversation buffer, demonstrated

The fourth turn produced the most interesting result in the evaluation. Asked *"What
was the very first thing I asked you?"*, **every scenario answered "What is ERA?"** —
which was Q2, not Q1.

This is the buffer working correctly, not a memory failure. Walking through the state
after four turns:

```
history      = [Q1, A1, Q2, A2, Q3, A3, Q4]     # 7 messages
history[-6:] =     [A1, Q2, A2, Q3, A3, Q4]     # keep the last 6
                    ^^ orphaned reply, trimmed
sent = [system prompt] + [Q2, A2, Q3, A3, Q4]   # window starts on a user turn
```

Q1 has aged out of the window, so the oldest message the model can still see is Q2 —
and both models accurately reported the earliest thing actually in their context.
Meanwhile the system prompt carrying both documents was still fully present, which is
why the same turn could still quote the sources. That is precisely the intended
design: **documents are permanent, conversation is a rolling window.** The on-screen
transcript still shows all four turns; only what is sent to the model is trimmed.

## Limitations

- The three questions were asked in sequence in a single conversation, so Q3 sees the
  Q1/Q2 exchange. This is deliberate — it is what exercises the memory — and it is
  symmetric across all six scenarios, so the model-vs-model comparison remains fair.
- One run per scenario. These models are non-deterministic, so small differences in
  phrasing or length would vary on a re-run. The coverage results (which facts each
  scenario could and could not supply) are structural and would not.
- Documents are truncated to 20,000 characters each. Both pages fit well under that
  limit, so nothing was cut in this evaluation.
